---
title: Expenses
description: Find, add, edit, and delete expenses from your terminal.
---

An expense records money you spent, when you spent it, and what it was for.
You can also connect it to an account, category, and tags.
For example, record 18.75 for Lunch, paid from Daily checking, in Food, with the Work tag.

## Before you start

- **Required:** finish the [Quick start](/docs/cli), including account setup and sign-in.
  Use an interactive terminal for the guided examples below.
- **Required for a new expense:** a positive amount of at least 0.01, in your Spendly currency.
- **Optional:** a description, account, category, and tags. To choose Daily checking,
  Food, or Work, those records must already exist in your own Spendly data.
  Otherwise, use your own names or leave them unassigned.
- **Automatic:** the date defaults to today. Account and category defaults are
  explained under **Things to know**.

## Try adding an expense

Already saved Lunch in Quick start or through an AI agent? Do not add it again.
Use [View expenses](#view-expenses) to find it or [Change an expense](#change-an-expense)
to correct it. The add walkthrough below is for a new purchase.

`--dry-run` lets you review an expense without saving it. Start with the guided
form:

```bash
spendly expenses add --interactive --dry-run
```

Enter `18.75` for the amount and `Lunch` for the description. Review the date,
then choose Daily checking, Food, and Work if you have them. The preview shows
the proposed expense and its effect on your balance.

<details className="docs-disclosure">
<summary>Alternative: enter the details as flags</summary>

```bash
spendly expenses add --amount 18.75 --spent-on "Lunch" \
  --account "Daily checking" --category "Food" --tag "Work" --dry-run
```

The quoted names must match your existing records. Omit those options if you
have not created the records yet.

</details>

## Check and save

1. Check the preview's amount, date, description, account, category, tags, and
   balance change.
2. Run the guided command again without `--dry-run`:

   ```bash
   spendly expenses add --interactive
   ```

   Enter the same details, review the new server preview, and confirm to save.
   Cancel if anything is wrong. A dry run does not carry your answers into this form.
3. Copy the saved expense's ID and verify it:

   ```bash
   spendly expenses get EXPENSE_ID
   ```

`EXPENSE_ID` is a placeholder for the ID of your expense, not its description.
You can also find it with `spendly expenses list --limit 25`.

For the direct alternative, run the same command without `--dry-run` to save.
A fully specified direct add does not open a confirmation prompt, so check its
preview first. Choose one save method; running both creates two expenses.

## Other things you can do

<details className="docs-disclosure">
<summary id="view-expenses">View expenses</summary>

Use guided filters to find Lunch or other spending:

```bash
spendly expenses list --interactive
```

Or list expenses directly:

```bash
spendly expenses list --limit 25
spendly expenses list --from 2026-09-01 --to 2026-09-30
spendly expenses get EXPENSE_ID
```

Dates use `YYYY-MM-DD`; both ends of the range are included. Replace the sample
dates with your own. Each list result includes an expense ID. Use
`spendly expenses list --help` for all filters, or `spendly summary --current`
for totals in the current cycle.

</details>

<details className="docs-disclosure">
<summary id="change-an-expense">Change an expense</summary>

If Lunch cost 20.25 instead, preview a correction. In guided mode, omit the ID
to choose an expense, then select the fields to change:

```bash
spendly expenses edit --interactive --dry-run
```

Or preview the amount change directly:

```bash
spendly expenses edit EXPENSE_ID --amount 20.25 --dry-run
```

Check the before-and-after values. To save with a review prompt, run
`spendly expenses edit EXPENSE_ID --interactive --amount 20.25`, then confirm.
Verify with `spendly expenses get EXPENSE_ID`. A direct edit without
`--interactive` or `--dry-run` saves without a confirmation prompt.

Only supplied fields change. To remove a value, use `--clear-category`
(move to Uncategorized), `--clear-account` (leave unassigned),
`--clear-spent-on` (remove the description), or `--clear-tags` (remove all tags).
Supplying tags during an edit replaces the tag selection; it does not append to it.
Changing the amount or account updates the affected balances.

</details>

<details className="docs-disclosure">
<summary id="remove-an-expense">Remove an expense</summary>

**Deletion is permanent.** If Lunch was recorded by mistake, preview the
expense before deleting it. If it used an account, deleting it adds its amount
back to that account's balance.

```bash
spendly expenses delete EXPENSE_ID --dry-run
```

Check the target and balance change. To delete, run the command without
`--dry-run` in your terminal and answer the confirmation prompt, which defaults
to No:

```bash
spendly expenses delete EXPENSE_ID
```

Verify using the **same expense ID** you just deleted:

```bash
spendly expenses get EXPENSE_ID
```

A successful deletion makes this lookup return `RESOURCE_NOT_FOUND` (exit code
4), rather than expense details. This is expected for the deleted ID, not a
reason to repeat deletion. A sign-in or connection error does not verify the
result; resolve that error and check the same ID again. Absence from the first
page of a list is not proof of deletion.

You can also use `spendly expenses delete --interactive --dry-run` to choose a
target for preview. A deletion dry run does not delete the expense, but it creates
a server-side confirmation record.

</details>

<details className="docs-disclosure">
<summary id="see-the-next-page-of-results">See the next page of results</summary>

Start with the filters you need:

```bash
spendly expenses list --account "Daily checking" --limit 25
```

If the result has a next cursor, copy that value unchanged. Replace `NEXT_CURSOR`
below with it, keeping the same filters and page size:

```bash
spendly expenses list --account "Daily checking" --limit 25 --cursor "NEXT_CURSOR"
```

Repeat only while a next cursor is returned. Use `spendly summary --current` for
totals, rather than adding up individual pages.

</details>

## Things to know

<details className="docs-disclosure">
<summary>Defaults, limits, and important behavior</summary>

- Add `--date 2026-09-05` to record a different date. Categories belong to cycles
  (your spending periods), so the expense date determines which categories apply.
- Guided adds show visible categories for the selected date's cycle, followed by
  Uncategorized. They do not infer a category automatically. A direct add that
  omits the category may reuse one from matching description history.
- An omitted account uses your default account when available; otherwise the
  expense remains unassigned. Use `--no-account` when adding to explicitly leave
  it unassigned. Clearing an account on an edit also updates its former balance.
- List pages contain at most 100 expenses. To see another page, pass the returned
  cursor (the marker for where the next page starts) with `--cursor` and keep the
  same filters.

</details>

## If something goes wrong

<details className="docs-disclosure">
<summary>Common problems and fixes</summary>

- **No expenses match:** the filters may exclude Lunch. Try
  `spendly expenses list --limit 25` without filters, then check the date range.
- **A name cannot be found:** check the spelling and use an existing name.
  Food must belong to the cycle containing the expense date.
- **A date change reports a category mismatch:** the old category belongs to a
  different cycle. Choose a category for the new date, or use `--clear-category`,
  then preview again.
- **The expense changed after you read it:** someone saved a newer version.
  Read it again with `expenses get`, review the current values, and rerun the
  preview before saving.
- **The command needs input but cannot prompt:** run guided commands in an
  interactive terminal. For automation, supply explicit inputs as described below.

</details>

## For scripts and AI agents

You can skip this reference when using guided commands.

<details className="docs-disclosure">
<summary>Optional: automation and technical reference</summary>

Use the [Spendly skill](/docs/cli/ai-agents) for the preview and confirmation
workflow. Scripts should use explicit commands with `--non-interactive`; names
are not accepted in this mode. Use stable IDs such as `--account-id`,
`--category-id`, and repeatable `--tag-id` instead.

### Write keys and revisions

An idempotency key identifies one intended write so a retry does not duplicate it.
Interactive commits generate a key when none is supplied. Non-interactive
commits require a fresh `--idempotency-key` of 8-200 characters. Reuse a key only
for an explicitly requested retry of that exact write, not a new expense or a
changed request. Dry runs do not require a write key.

Non-interactive edits, including previews, require `--if-revision` with the
current revision from `spendly expenses get EXPENSE_ID`. A revision is the
expense's version number; this check prevents a stale edit from overwriting a
newer change. After a conflict, read the expense again and rerun the dry run.
Do not silently substitute a newer revision and commit an old proposal.

### Deletion confirmation

A non-interactive deletion requires `--confirmation-token`, `--if-revision`,
and `--idempotency-key`. Obtain the token and revision from a deletion dry run.
The token is single-use, bound to that expense and revision, and valid for five
minutes. Do not supply a token or revision to `delete --dry-run`: it creates a
new confirmation. If the preview expires or the expense changes, obtain and
review a new preview before deletion. See `spendly expenses delete --help` for
the options.

</details>
