---
title: Authentication
description: Sign in safely through your browser and understand local credential storage.
---

Spendly CLI uses browser-based OAuth with PKCE. It never asks you to paste a
password, session token, Clerk secret, or Convex deploy key into the terminal.

## Sign in

```bash
spendly auth login
```

The CLI opens your browser and listens on a random loopback port on
`127.0.0.1`. Complete sign-in in the browser, then return to the terminal.

If automatic browser opening is unavailable:

```bash
spendly auth login --no-browser
```

Open the displayed URL on the same computer. Do not send it to another person
or paste it into an external service.

## Verify the session

Human-readable status:

```bash
spendly auth status
```

Machine-readable status:

```bash
spendly --json --non-interactive auth status
```

Authorization lasts for at most 30 days and may be refreshed during that
period. Expired or invalid credentials require a new browser login.

## First-time account setup

If the CLI returns `ACCOUNT_SETUP_REQUIRED`, authentication succeeded but the
Spendly backend user does not exist yet. Open Spendly Web once while signed in,
then rerun:

```bash
spendly context
```

The CLI will not silently create the backend user or onboarding data.

## Credential storage

By default, Spendly uses the operating system credential store. If the keychain
is unavailable, the CLI stops with `KEYCHAIN_UNAVAILABLE`.

Plaintext file fallback is opt-in only:

```bash
spendly --allow-file-storage auth login
```

Use this only on a trusted computer with an owner-only filesystem. Never ask an
agent to inspect the keychain entry or credential file.

## Sign out

```bash
spendly auth logout
```

Logout removes local access and attempts to revoke the provider session. It
does not delete your Spendly account or financial records.
