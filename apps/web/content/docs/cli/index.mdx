title: Quick start

Spendly CLI lets you track expenses from your terminal using the same data as
Spendly Web. For example, you can record Lunch and check your account balance
without opening the web app.

Prefer to ask an AI agent? After installing and signing in below, continue to
[AI agents](/docs/cli/ai-agents) for Codex or Claude Code. You do not need to
learn the expense commands first.

## Before you start

- **Required:** Node.js 22+, a [Spendly account](/sign-up), and completed Web setup.
- **Platform:** macOS is verified. Linux verification is planned; Windows is unsupported.
- **Safety:** use a trusted computer. Never share sign-in links or credentials.
- **Optional:** accounts, categories, and tags. You can organize the expense later.

## Open your terminal and check Node.js

On macOS, press Command-Space, type **Terminal**, and press Enter. This is where
you run commands. Copy only the command text, not the surrounding backticks.

Check that Node.js and npm (the tool that installs Spendly) are available:

```bash
node --version
npm --version
```

Node.js must have a major version of 22 or higher. If either command is missing,
or Node.js is too old, follow the [Node.js installation instructions](https://nodejs.org/en/download).
Choose a supported LTS release, then open a new terminal and check again.

## Install and sign in

Choose your installed package manager in the tabs; the choice stays in sync
across these docs. Not sure? Use **npm**, which comes with Node.js.
These commands install the latest release:

```bash
npm install --global spendly@latest
spendly --version
spendly auth login
```

Installation makes the `spendly` command available. Complete sign-in in the
browser, then return to your terminal and check your session:

```bash
spendly auth status
```

## Try your first expense

The `--interactive` option opens a guided form. The `--dry-run` option previews
this expense without saving it:

```bash
spendly expenses add --interactive --dry-run
```

Use a real purchase. Enter its amount in the shown currency, description, and
date - for example, `18.75` for `Lunch`.

Choose existing records, or leave the category **Uncategorized**, account
**unassigned**, and tags empty. Use arrow keys and Enter; Escape or Ctrl-C cancels.

For a screen reader or a terminal that has trouble redrawing lines, add
`--accessible` to the command for static numbered prompts.

## Check and save

Check every detail and the balance change. To save, reopen the form without
`--dry-run`, enter the same details, review, and confirm:

```bash
spendly expenses add --interactive
```

Keep the saved expense's ID (its unique identifier) and date. Later pages update
this same Lunch; do not record it again.

Verify that Lunch appears in your expenses, then check your balances:

```bash
spendly expenses list
spendly accounts list
```

If the save result is unclear, check your expenses before trying again. A lost
response does not mean the save failed; see
[Troubleshooting](/docs/cli/troubleshooting) before repeating a write.

## Other things you can do

<details className="docs-disclosure">
<summary>Balances, summaries, help, and signing out</summary>

See your currency, current cycle (your spending period), and spending summary:

```bash
spendly context
spendly summary --current
```

Open the guided menu to find more actions, or ask for help with a command:

```bash
spendly --interactive
spendly --help
spendly expenses add --help
```

To sign out and remove your locally stored session:

```bash
spendly auth logout
```

</details>

## Things to know

<details className="docs-disclosure">
<summary>Defaults, limits, and important behavior</summary>

- Authorization lasts at most 30 days before browser sign-in is required again.
- Guided category choices come from the cycle covering the selected date,
  followed by Uncategorized. The automatic category inference available when
  scripts omit a category is not a guided choice.
- Flags you supply are kept when you open the guided form.
- Production authentication and read-only use through the Spendly skill in Codex
  have been verified; broader production workflows remain subject to ongoing
  validation.

</details>

## If something goes wrong

<details className="docs-disclosure">
<summary>Common problems and fixes</summary>

- **Command not found:** Your terminal cannot locate Spendly. Check installation
  and your terminal's command search path using [Troubleshooting](/docs/cli/troubleshooting).
- **Sign-in or setup required:** Run `spendly auth login`, or finish account
  setup in Spendly Web, then check `spendly auth status`.
- **Prompts unavailable:** Guided forms need an interactive terminal. See
  [Troubleshooting](/docs/cli/troubleshooting) for redirected input and accessible prompts.

</details>

## For scripts and AI agents

You can skip this reference when using guided commands.

<details className="docs-disclosure">
<summary>Optional: automation and technical reference</summary>

Use explicit commands with `--non-interactive`, for example:

```bash
spendly --agent --json --non-interactive context
```

`--agent` and `--json` never prompt, even in a terminal. Missing required inputs
produce an error instead of waiting. Do not combine these modes or
`--non-interactive` with `--interactive`. See [AI agents](/docs/cli/ai-agents)
for machine-readable output, write safeguards, and privacy boundaries.

Bare `spendly` opens the menu only when both input (stdin) and prompt output
(stderr) are terminals (TTYs). Otherwise it prints help and exits without
prompting. Use `spendly --interactive` to explicitly open the menu. Explicit
commands, `--help`, and `--version` keep their existing behavior.

In guided forms, `›` marks the focused choice. Tags and filters use checkbox
selections. In date inputs, brackets mark the active segment, such as
`[2026]-09-15`: Left/Right changes the segment and Up/Down changes its value.
Accessible mode uses numbered choices, comma-separated checkbox selections,
plain yes/no confirmations, and no ANSI cursor movement. Enable it with
`--accessible` or `ACCESSIBLE=1`; Spendly selects it automatically when
`TERM=dumb`. Color is never required to understand focus, warnings, or errors.

For shell completion, generate the script for your shell and follow that shell's
normal sourcing setup:

```bash
spendly completion zsh
spendly completion bash
spendly completion fish
```

</details>
