---
title: Cycles
description: Create, inspect, edit, and safely delete spending periods.
---

A cycle groups spending into a period, such as one month. It has its own
categories and budget, shared with Spendly Web.

## Before you start

- [Install and sign in](/docs/cli); use a terminal for guided commands.
- Have a name and date range ready. Copying categories is optional.
- A new cycle does not automatically attach older expenses or create categories.

Dates use `YYYY-MM-DD`. For a September example:

| Field | Value | Meaning |
| --- | --- | --- |
| Start | `2026-09-01` | First included day |
| End | `2026-10-01` | First day **not** included |

Start must be before end. Cycles cannot overlap; the next may start on the
previous one's end date. Use dates covering your saved Lunch, not necessarily
these examples.

**Already have a matching cycle?** Reuse it and skip creation. Check first:

```bash
spendly cycles list
```

## Try creating a cycle

`--dry-run` checks your inputs and shows a preview without saving the cycle.
Use it with the guided form:

```bash
spendly cycles add --interactive --dry-run
```

For the example, enter `September 2026`, start date `2026-09-01`, and end date
`2026-10-01`. Choose not to copy categories if this is your first cycle.

<details className="docs-disclosure">
<summary>Alternative: enter the details as flags</summary>

```bash
spendly cycles add --name "September 2026" \
  --start-date 2026-09-01 --end-date-exclusive 2026-10-01 --dry-run
```

</details>

## Check and save

1. Read the preview. Check the name, dates, and any categories or planned
   amounts you chose to copy.
2. Run the same command without `--dry-run` to save. In guided mode, enter your
   choices again, review the new preview, and confirm.
3. Find the saved cycle and inspect it:

```bash
spendly cycles list
spendly cycles get CYCLE_ID
```

Replace `CYCLE_ID` with the ID from the list. An ID uniquely identifies a cycle;
two cycles can share the same name. Check the saved name and dates.

## Other things you can do

<details className="docs-disclosure">
<summary id="view-a-cycle-and-its-spending">View a cycle and its spending</summary>

```bash
spendly cycles current
spendly cycles current --date 2026-09-05
spendly summary --cycle-id CYCLE_ID
spendly expenses list --cycle-id CYCLE_ID
```

`current` finds the cycle containing today's local date, or the date you supply.
If no cycle contains that date, it returns no cycle, not the newest cycle.
The summary shows spent, planned, and remaining amounts with a category
breakdown. The expense list is paginated. Use `spendly summary --current` for
today's cycle.

</details>

<details className="docs-disclosure">
<summary id="add-the-next-cycle-with-copied-categories">Add the next cycle with copied categories</summary>

Copy categories to reuse Food and its budget next month. Replace
`SOURCE_CYCLE_ID` with the existing cycle's ID:

```bash
spendly cycles add --name "October 2026" \
  --start-date 2026-10-01 --end-date-exclusive 2026-11-01 \
  --copy-from-cycle-id SOURCE_CYCLE_ID --include-planned-amounts --dry-run
```

Check the preview, then repeat without `--dry-run` to save. Verify with
`spendly cycles list` and `spendly categories list --cycle-id CYCLE_ID`, using
the **new** cycle's ID.

This copies all source categories, including hidden ones. Without
`--include-planned-amounts`, copied categories have no planned amounts unless
you supply overrides. Names, order, icons, visibility, and category types are
preserved, but each copy gets a new category ID. Expenses are never copied.

Guided creation offers all, some, or no categories, then keep/set/clear choices
for their planned amounts. These choices also work with accessible static
prompts. Selecting an empty subset copies none. For direct selection and budget
overrides, see [For scripts and AI agents](#for-scripts-and-ai-agents).

</details>

<details className="docs-disclosure">
<summary id="change-a-cycle">Change a cycle</summary>

Preview a name or date change, or use the guided form:

```bash
spendly cycles edit CYCLE_ID --name "September spending" --dry-run
spendly cycles edit CYCLE_ID --end-date-exclusive 2026-10-05 --dry-run
spendly cycles edit --interactive --dry-run
```

Only supplied fields change. New dates still cannot overlap another cycle.
**Existing expenses are not reassigned or recategorized.** They stay linked to
the original cycle even if their dates now fall outside it. A later expense edit
checks date and category compatibility again.

Review the before-and-after preview. Run your chosen command without
`--dry-run`, confirm, then run `spendly cycles get CYCLE_ID` to verify.
Category copying is available only at creation; manage existing category plans
separately.

</details>

<details className="docs-disclosure">
<summary id="remove-an-empty-cycle">Remove an empty cycle</summary>

**Deletion is permanent and removes every category in the cycle.** It is blocked
while any expense is linked to the cycle, including uncategorized expenses and
expenses outside an edited date range. There is no force-delete option.

Preview the loss first:

```bash
spendly cycles delete CYCLE_ID --dry-run
```

This preview creates a short-lived confirmation record, but makes no financial
change. Check the cycle and category count. To delete, run the following in a
terminal and confirm only if the preview is correct:

```bash
spendly cycles delete CYCLE_ID
```

Run `spendly cycles list` afterward to verify that the cycle is gone.

</details>

<details className="docs-disclosure">
<summary id="correct-an-expense-blocking-deletion">Correct an expense blocking deletion</summary>

Only do this when the expense's saved date is wrong, or its link is out of date
after a cycle-date edit. If the expense belongs in this cycle, **keep the cycle**.

1. List linked expenses with `spendly expenses list --cycle-id CYCLE_ID`.
2. Replace `EXPENSE_ID` below with the expense's ID and `YYYY-MM-DD` with its
   actual spending date. Check that another cycle covers that date.
3. Preview the correction. `--clear-category` removes the old cycle's category;
   it does not delete the expense.

```bash
spendly expenses get EXPENSE_ID
spendly cycles current --date YYYY-MM-DD
spendly expenses edit EXPENSE_ID --date YYYY-MM-DD --clear-category --dry-run
```

Check the date and destination cycle. If correct, run the edit without
`--dry-run` to save immediately. Verify with `spendly expenses get EXPENSE_ID`.
The amount and account should be unchanged. Choose a destination category later
using [Categories](/docs/cli/categories).

Check the old cycle's expense list again, including any further pages. Only
preview cycle deletion again when no expenses remain linked. Do not delete real
expenses just to empty a cycle.

</details>

## Things to know

<details className="docs-disclosure">
<summary>Defaults, limits, and important behavior</summary>

- Creating a cycle does not move existing expenses into it. Copying categories
  does not copy expenses either.
- Changing cycle dates does not move or fix existing expenses. Review linked
  expenses before changing the date range.
- A planned amount is a category's budget, not an expense. Copying a budget does
  not record any spending.
- A deletion preview expires after five minutes. Changes to the cycle or its
  categories require a fresh preview. Deletion restrictions are checked again
  when saving.

</details>

## If something goes wrong

<details className="docs-disclosure">
<summary>Common problems and fixes</summary>

- **No current cycle:** no cycle covers the requested date. Check
  `spendly cycles list`, then use the right date or create a cycle for that period.
- **Dates overlap:** another cycle already covers part of the range. Check its
  dates before choosing a different range.
- **Cycle has expenses:** keep it if those expenses belong there. If an expense
  has the wrong saved date, [correct it first](#correct-an-expense-blocking-deletion).
  Never change a real expense date just to make deletion possible.
- **Cycle or copied categories changed:** your preview is out of date. Read the
  current state and review a fresh preview before approving a new write.
- **Confirmation expired:** preview deletion again and review it before saving.
- **Connection failed while saving:** first check whether the change was saved.
  Do not blindly repeat the write. See the recovery details below and
  [Troubleshooting](/docs/cli/troubleshooting).

</details>

## For scripts and AI agents

You can skip this reference when using guided commands.

<details className="docs-disclosure">
<summary>Optional: automation and technical reference</summary>

Cycle changes also require a compatible Spendly service. If commands are
available but the service rejects them, stop and report the error through
[Troubleshooting](/docs/cli/troubleshooting).

### Non-interactive writes

Use `--agent --json --non-interactive` for agent calls. JSON and agent modes do
not prompt; supply all required inputs. Non-interactive writes require a unique
`--idempotency-key` for each intended operation. This key lets the backend return
the saved result if the same operation is repeated after a lost response.
A dry run needs no key.

Edits and deletions also require `--if-revision`. Use the revision returned by
`get` or the relevant preview. Deletion requires the confirmation token from its
preview as well; provide the token and revision together. Do not pass either to
`delete --dry-run`, which creates a new confirmation.

```bash
spendly --agent --json --non-interactive cycles get CYCLE_ID
spendly --agent --json --non-interactive cycles edit CYCLE_ID \
  --name "September spending" --if-revision REVISION --idempotency-key EDIT_KEY
spendly --agent --json --non-interactive cycles delete CYCLE_ID --dry-run
spendly --agent --json --non-interactive cycles delete CYCLE_ID \
  --confirmation-token TOKEN --if-revision REVISION --idempotency-key DELETE_KEY
```

Replace uppercase placeholders with actual IDs, returned values, and fresh keys
for new operations. Review the current cycle before editing and the deletion
preview before deleting. **The deletion command permanently removes the cycle
and all its categories.** Verify changes with `cycles get` or `cycles list`.
Creation uses the flags from the human example plus an idempotency key.

Successful creation returns `data.cycle` and `data.copiedCategories`; editing
returns the cycle directly. Deletion returns `data.deleted`, the former cycle,
and `data.deletedCategoryCount`.

Deletion tokens expire after five minutes. They are bound to the user, cycle
revision, and category snapshot, so changes to either the cycle or its categories
require a fresh preview. Restrictions are checked again at deletion.

### Select copied categories and override budgets

Repeat `--copy-category-id` to choose a subset. Use **source category IDs** for
selections and overrides. For example, replace `FOOD_ID` and `OTHER_CATEGORY_ID`
with IDs from `spendly categories list --cycle-id SOURCE_CYCLE_ID`:

```bash
spendly cycles add --name "October 2026" \
  --start-date 2026-10-01 --end-date-exclusive 2026-11-01 \
  --copy-from-cycle-id SOURCE_CYCLE_ID \
  --copy-category-id FOOD_ID --copy-category-id OTHER_CATEGORY_ID \
  --include-planned-amounts --planned-amount FOOD_ID=200 \
  --clear-planned-amount OTHER_CATEGORY_ID --dry-run
```

This previews a Food budget of 200 and no planned amount for the other category.
Review it before saving, then verify the new cycle's category list. Planned
amounts must be nonnegative decimals, including zero. Each category can have
only one override; overrides take precedence over copied amounts. Selected and
overridden categories must belong to the source cycle.

To explicitly copy none, use `--without-categories` instead of selection or
budget flags. Copy selection and budget flags require `--copy-from-cycle-id`.

### Keep a separately reviewed copy unchanged

Copying writes automatically obtain and commit the same snapshot in guided,
human, and direct modes. A snapshot identifies the exact category data to copy.
For a separately reviewed dry run, capture `data.copySnapshot` and pass it as
`--if-copy-snapshot HASH` when saving. Keep the source, category selections, and
plan inputs identical.

The snapshot is a 64-character lowercase hex SHA256 value. It binds the source
ID and every effective persisted category-copy field: selected IDs, names,
types, plans, icons, hidden state, and order. It is **not** the source cycle
revision. A source with explicit copy-none still gets a guard for the empty
effective selection; creation without a source is unchanged.

`--if-copy-snapshot` requires `--copy-from-cycle-id` and cannot be combined with
`--dry-run`. Review the first result below, then replace `HASH` with its
`data.copySnapshot` and `CREATE_KEY` with a fresh key:

```bash
spendly --agent --json --non-interactive cycles add --name "October 2026" \
  --start-date 2026-10-01 --end-date-exclusive 2026-11-01 \
  --copy-from-cycle-id SOURCE_CYCLE_ID --include-planned-amounts --dry-run
spendly --agent --json --non-interactive cycles add --name "October 2026" \
  --start-date 2026-10-01 --end-date-exclusive 2026-11-01 \
  --copy-from-cycle-id SOURCE_CYCLE_ID --include-planned-amounts \
  --if-copy-snapshot HASH --idempotency-key CREATE_KEY
```

### Conflicts and uncertain writes

`CYCLE_OVERLAP`, `CYCLE_HAS_EXPENSES`, `CYCLE_REVISION_CONFLICT`, and
`CYCLE_COPY_CONFLICT` use conflict exit code 5. A stale-copy failure must stop
for a fresh preview and approval; do not blindly retry or change the payload.
Invalid inputs use exit code 2; missing or foreign records use
`RESOURCE_NOT_FOUND` (4); invalid or expired confirmation tokens use exit code 6.
Read again and review a fresh preview after a conflict.

A lost response is different: the write may already have succeeded. Preserve
its exact inputs and original key. Human network errors print the resolved
recovery inputs, including an automatically generated key and any copy
snapshot, revision, or token. After checking current state and explicitly
choosing recovery, use those inputs with `--non-interactive` and the **same
agent mode**.

This recovery bypasses a fresh preview/read so the backend can replay a saved
result even after an edit changed the revision or a deletion removed the cycle.
For copying creation, an explicit snapshot with `--non-interactive` makes no new
preview/source read: backend idempotency returns a saved result before checking
the guard, even if the source later changed or was deleted.

For the same uncertain write, keep its original snapshot, revision, token, and
key; do not substitute new values. See
[Troubleshooting](/docs/cli/troubleshooting).

</details>
